# แผนการทดสอบระบบสแกนใบหน้า (Face Authentication Test Plan)
**ระบบกายภาพบำบัดโรงพยาบาล (Hospital PT System)**

เอกสารนี้จัดทำขึ้นตามข้อกำหนด **Section 6.4** เพื่อเป็นแนวทางสำหรับคณะทำงาน, เจ้าหน้าที่เทคนิค และทีมแพทย์/DPO ในการทดสอบและปรับเทียบค่าความแม่นยำของระบบสแกนใบหน้ากับคนจริงก่อนเริ่มใช้งานจริงในโรงพยาบาล

---

## 1. วัตถุประสงค์การทดสอบ
1. วัดผล **False Acceptance Rate (FAR)**: โอกาสที่บุคคลอื่นจะถูกระบบรับรองผิดว่าเป็นคนไข้ตัวจริง
2. วัดผล **False Rejection Rate (FRR)**: โอกาสที่คนไข้ตัวจริงจะถูกระบบปฏิเสธ
3. ทดสอบความสามารถในการป้องกันการปลอมแปลง (Liveness Anti-Spoofing): ปฏิเสธรูปถ่าย, วิดีโอบนสมาร์ตโฟน, และหน้ากาก
4. ยืนยันการปฏิบัติตามมาตรฐาน PDPA: ข้อมูลภาพไม่ถูกเก็บถาวร, เก็บเฉพาะ 512-dim embedding เข้ารหัส

---

## 2. ตารางบันทึกผลการทดสอบ (Test Scenarios Matrix)

| รหัสทดสอบ | เงื่อนไขการทดสอบ | ขั้นตอนดำเนินการ | ผลลัพธ์ที่คาดหวัง | เกณฑ์ผ่าน | บันทึกผลจริง |
|:---|:---|:---|:---|:---:|:---:|
| **TC-01** | แสงสว่างปกติในห้องตรวจ (300-500 Lux) | คนไข้จริงยืนห่างจาก Kiosk 50-70 ซม. มองตรงตามคำสั่ง 2 ท่า | ผ่านการยืนยันตัวตน และได้รับบัตรคิวในเวลา < 3 วินาที | ต้องผ่าน 100% | |
| **TC-02** | แสงน้อย / ย้อนแสง (100 Lux หรือมีหน้าต่างด้านหลัง) | คนไข้จริงยืนในจุดที่มีแสงย้อน | ระบบตรวจจับความสว่าง/ความคมชัด หากต่ำเกินไปจะแจ้งเตือนให้ปรับตำแหน่ง | ห้าม Match ผิดคน | |
| **TC-03** | การสวมแว่นสายตา (Eyewear) | คนไข้ที่ลงทะเบียนแบบไม่สวมแว่น ➔ ทดลองสวมแว่นสายตากรอบใส/กรอบดำ | ระบบยังสามารถสกัด Landmark รอบดวงตาและจมูกเพื่อยืนยันตัวตนได้ | ผ่าน > 95% | |
| **TC-04** | การสวมแว่นกันแดดทึบแสง (Sunglasses) | คนไข้สวมแว่นตาดำบดบังดวงตา | ระบบปฏิเสธการสแกนและขอให้ถอดแว่นกันแดด | ต้องปฏิเสธ 100% | |
| **TC-05** | การสวมหน้ากากอนามัย (Surgical Mask) | คนไข้สวมหน้ากากอนามัยปิดปากและจมูก | ระบบปฏิเสธและแจ้งเตือนให้ปลดหน้ากากอนามัยชั่วคราว หรือใช้เบอร์โทรศัพท์แทน | ต้องปฏิเสธ 100% | |
| **TC-06** | การใช้รูปถ่ายนิ่ง (Photo Print / 2D Paper) | นำภาพถ่ายสีขนาดเท่าใบหน้าจริงมาจ่อหน้ากล้อง | ระบบไม่ผ่านขั้นตอน **2-Step Liveness Motion** (หันซ้าย/ขวา/พยักหน้า) ภายใน 60 วินาที | ต้องปฏิเสธ 100% | |
| **TC-07** | วิดีโอบนสมาร์ตโฟน (Video Replay Attack) | เล่นวิดีโอที่บันทึกคนไข้กำลังหันศีรษะผ่านหน้าจอมือถือ | ระบบไม่สามารถตอบสนองต่อ Challenge สุ่ม 2 ท่าทางแบบเรียลไทม์ได้ถูกต้องตรงกัน | ต้องปฏิเสธ 100% | |
| **TC-08** | ฝาแฝดหรือญาติสายเลือดใกล้ชิด (Close Relatives) | ให้พี่น้อง/ฝาแฝดที่ไม่ใช่คนไข้มาสแกน | ค่า Margin Check (0.10) จะตรวจจับความกำกวม และบังคับ Fallback สู่เบอร์โทรศัพท์ | ห้ามออกคิวผิดคน | |
| **TC-09** | ล้มเหลวครบ 3 ครั้ง (3-Strike Fallback) | บุคคลภายนอกที่ไม่มีใบหน้าในระบบพยายามสแกน 3 ครั้งติดต่อกัน | ระบบล็อกหน้าสแกนชั่วคราว และเปลี่ยนเส้นทางไปยังหน้ากรอกเบอร์โทรศัพท์อัตโนมัติ | ทำงานอัตโนมัติ | |
| **TC-10** | การหมดเวลาไม่ใช้งาน (Inactivity Timeout) | เปิดหน้าสแกนทิ้งไว้ 45 วินาทีโดยไม่มีการสัมผัสหรือเคลื่อนไหว | ระบบนับถอยหลังและกลับสู่หน้าแรก (Welcome Screen) อัตโนมัติ | กลับหน้าแรก | |

## 3. เกณฑ์การปรับเทียบค่าพารามิเตอร์ (Calibration Guidelines)

ค่าพารามิเตอร์หลักถูกกำหนดไว้ในไฟล์ `.env.local`:
```env
# ค่าความคล้ายคลึงขั้นต่ำ (Cosine / Euclidean Distance)
# ยิ่งต่ำ ยิ่งเข้มงวด (แนะนำระหว่าง 0.55 - 0.62)
FACE_SIMILARITY_THRESHOLD=0.60

# ค่าระยะห่างขั้นต่ำระหว่างอันดับ 1 และอันดับ 2 เพื่อป้องกันการระบุตัวตนกำกวม
FACE_MATCH_MARGIN=0.10
```

### คำแนะนำการปรับแต่ง:
- **หากพบคนไข้ตัวจริงถูกปฏิเสธบ่อย (FRR สูงเกินไป)**:
  - ให้ปรับ `FACE_SIMILARITY_THRESHOLD` ขึ้นทีละ 0.02 (เช่น 0.60 ➔ 0.62)
  - ตรวจสอบความสว่างของแสงบริเวณที่ติดตั้งตู้ Kiosk (ควรมีไฟ LED เสริมด้านหน้าตู้)
- **หากพบระบบให้คนอื่นผ่าน (FAR ไม่เป็นศูนย์)**:
  - ให้ลด `FACE_SIMILARITY_THRESHOLD` ลง (เช่น 0.60 ➔ 0.58)
  - เพิ่ม `FACE_MATCH_MARGIN` เป็น 0.12 เพื่อเพิ่มความปลอดภัย

## 4. ข้อพิจารณาทางกฎหมายและ PDPA
1. การสแกนใบหน้าที่ตู้ Kiosk จะสกัดเฉพาะตัวเลขเวกเตอร์ 128 มิติ (Biometric Template Vector) และส่งไปยังเซิร์ฟเวอร์ **โดยไม่มีการส่งภาพถ่ายใบหน้าดิบผ่านระบบเครือข่าย**
2. ข้อมูลชีวมาตรจะถูกจับคู่เฉพาะกับคนไข้ที่ได้ลงนามหนังสือยินยอม (Consent) ในขั้นตอนลงทะเบียนแล้วเท่านั้น
3. ทุกครั้งที่มีการตรวจสอบตัวตน (ทั้งสำเร็จและล้มเหลว) ระบบจะบันทึก Log ลงในตาราง `audit_logs` แบบ Insert-Only โดยไม่บันทึกเวกเตอร์ เพื่อความปลอดภัยสูงสุด
